# astra-2

`multi-arb` の市場正規化・クロス会場裁定・参照価格裁定を土台にした新レジーム専門型。
参照実装は変更せず、他プレイヤーの実装は参照していない。

- 通常時: WETH/WBTC の実行価格差を手数料とスリッページ余裕込みで比較。
  2脚とも取引前の在庫で支払い可能な額に制限。1回最大1,500 USDC相当。
  非原子的バンドルなので片脚のみの約定リスクは残る。
- spike: 参照価格の急変後3ブロックは方向性を増やす単脚を停止し、両脚裁定を継続。
  単脚最大700 USDC相当、基軸資産在庫は初期枚数の65–135%を目安に制御。
- cdp-incident: 正常/Recovery Modeの清算条件とSP全債務カバーを判定して清算報酬を狙う。
  eUSDは市場価格・償還料・売却費用・価格影響を比較し、最大1,200 USDCで償還裁定。
  自身の借入・新規SP預入はしない。受取ETHは初期1 ETH以上を残してwrapし、観測残高で売却確認。
- depeg-persist: DAIの割安だけでは買わない。4回連続の回復確認後、最大350 USDCで1回だけ購入。
  損切り・利確・18ブロック保有期限を置き、買い増さない。
- launch: 3ブロック連続の外部買いフロー確認後、最大250 USDCかつ準備金1%以下。
  同時1ポジション、累計購入予算750 USDC。残り60ブロックから新規購入停止。
  残り24ブロック・保有20ブロック・売りフロー・損切り・利確・追跡ストップで全量売却を試みる。
  残り6ブロック以下はquote失敗時にも最低受取量1で緊急売却。dustも放棄せず残高ゼロを確認する。

罠検査は認証済みV3プール、routerのfactoryによるプール一致、登録時からのコードハッシュ一致、
トークンのselector/opcode検査、往復quote、予定サイズのtransfer模擬呼び出し。
承認先は標準routerのみ、承認額は取引額ちょうど。
これは任意のERC20の安全性の証明ではない。独自の内部課税・送信者条件・流動性撤去は残存リスク。
厳しい検査により正当なトークンを見送る可能性もある。

RPCはread-onlyの渡されたclientだけを使用。個別180ms、最大18呼び出し/判断、
未完了要求も最大18。失敗時は通常裁定へ戻り、生のエラー文字列をログへ出さない。
設定はparams.tsの既定値、乱数なし。終了時刻不明なら新規専門ポジションを作らない。

再起動時は公開registryから1プール/判断で未知保有を再発見して売却する。
registryから消えた保有・再起動で失った累計購入予算・実際の送信遅延は完全には復元できない。
未約定のlaunch/eUSD購入は重複発注しないため、失敗が確定してもその専門戦略の機会を逃す場合がある。
prompt.mdはPARAMS/ガード調整のみを許し、状態や完全なexecutorを維持できない改訂はnullを指示する。

予想: CDP障害、会場価格差を伴うspike、買い需要のあるlaunchが得意。
需要のないlaunch、価格差の小さいcalm、回復しないDAIでは収益機会が少ない。
広い価格差でも他者の先行約定や片脚失敗で損失になり得る。優位性・順位は未測定。
