## 第1実験（一番安く、推論が効くかを決める）
1. 認証が通る状態で、スキーマに合う改訂を1回成功させる（これは前提で、価値の証拠ではない）。
2. 静かな場・活発な場・不利な局面から、改訂ポイントを数か所あらかじめ選ぶ。モデルには、その時点で分かる情報だけを渡す。
3. 各ポイントで改訂を1回ずつ生成し、「変更なしのベース」対「改訂版」を、同じ状態・同じ乱数・同じ相手ロスターで、エポック決済まで再生して比べる。
4. 測るもの: 形式・導入の成功率、PnL とスコアの対差、失敗数、費用。
5. 事前に、改善の基準と許容する悪化を決めておく。一貫した改善があれば広げる。不正な出力・明確な悪化・曖昧な結果なら、凍結ベースラインを採用。

## 案B: 外的環境で戦略を切り替える（3パターン、zeta-r2/r3 の強みを使う）
推論とは独立に進められる。推論なしでも成立する。
- 発想: 周りの参加者の活発さ（場）によって勝つ戦略が違う。静かな場・混在の場では zeta-r2/r3 が強く、活発な場では opus-1 が強い（zeta は活発な場で約47）。場ごとに最も強い戦略を割り当て、1つのエージェントにまとめる。
- 3パターン（案）: 静かな場 = zeta-r2、混在の場 = zeta-r3 か opus-1 の強い方、活発な場 = opus-1。割り当ては、場ごとの実際の対戦結果で決める。
- 切り替えの合図: エージェントが自分で観測できる値だけを使う（チェーン上の取引量、他者のスワップ頻度、価格のずれの頻度など）。場の判定が外れると、弱い戦略を選ぶ。
- 前提と制約: (1) 3つの戦略を1つのファイルに統合する必要がある（opus-1 は import が多く、zeta 側と衝突しないか要確認）。(2) 切り替えの頻度が高いと、ポジションの持ち越しで損が出る。エポック単位などで固定する。(3) 以前の評価では、理想的に切り替えられた場合でも、opus-1 単独に対する改善は小さかった。
- 判断ゲート（先に決める）: 場の判定を実際の観測値でやった場合の改善が、opus-1 単独より一貫して大きいこと（複数シード、触らない保留シード）。小さい・不安定なら採用しない。
- 手順: ①場を判定する観測値を、既存の実行ログから候補出しし、場ごとに分離できるか見る。②判定が外れた場合の損失を含めた、オラクル（正解を知っている）との差を測る。③統合した1ファイルを作り、実際の場で対戦。④gate を通れば、推論なしの候補として 10/29 の候補に入れる。
