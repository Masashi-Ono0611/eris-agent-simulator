# G3 要件4: 既存の事後結合器との差分と最小追加 — 2026-10-11

**G3（Gate 3、自己改訂を実チェーンで受け入れるための判定）は BLOCKED のまま。** 本書は要件4（実取引境界の残高・支出先別許可額・予約・ガス費と予備・receipt（採掘後の実行結果）・events/blocks（イベント記録とブロック表）との完全対応、[G3-PREREQ-2026-10-07.md:71-81](G3-PREREQ-2026-10-07.md#実recorderに不足するもの)）について、既存の検査で覆える範囲と不足を整理し、追加する人工入力専用（SYNTHETIC）の検査を最小に決めるもの。実観測、実チェーン、実記録器を扱わず、要件4全体を成立させない。

根拠として読んだ資料: [期限計画 要件4](G3-REQ25-PLAN-2026-10-11.md#要件4-取引境界の経済値採掘結果全対応)、[取引境界の採取設計](G3-B04-CAPTURE-DESIGN-2026-10-10.md)（以下「設計」）の §2.4 J01〜J14 と §5.2 P01〜P07、既存の事後結合器 [join.py](g3/posthoc-join/join.py) と [検証記録](g3/posthoc-join/VALIDATION.md)（53件のテスト）、要件2・要件3の人工結合器 [source-join.mjs](g3/loader/source-join.mjs)・[decision-join.mjs](g3/loader/decision-join.mjs) とそのテスト・変異検査。

## 2. 最小の追加作業

新設は `g3/loader/boundary-join.mjs` の純粋関数 `joinBoundaries(input)` だけ。既存の J06〜J08 を再計算せず、取引ごとに「既存事後結合器の J06・J07・J08 の判定」を投影した値として受け取り、`PASS` 以外をそのまま BLOCKED / FAIL に伝える。出力試行は要件3人工結合器の出力（判断識別子・経路・経路内順番・親処理）の投影として受け取る。どちらも人工入力で宣言された投影であり、join.py や decision-join.mjs を実行した結果ではない。

注意: 実際の join.py は4ファイルに receipt 全文が無いため J06 を常に BLOCKED とする。従って既存の事後結合器の実出力を本検査へ渡した場合は必ず BLOCKED になる。人工入力の正常ケースだけが `CONTRACT_OK_ON_SYNTHETIC` になり得る。

追加する検査（診断コードは `REQ4_<検査識別子>_<内容>`）:

- **J11**: 境界ごとに、支出する各 token の残高、(token, owner, spender) 別の allowance を要求する。観測の可否 `availability` が `observed` 以外（欠測・読取失敗・曖昧・導出値）、値が `null`、観測ブロックが境界と違う、別 spender の値しかない場合は BLOCKED。同じ鍵で値が異なる重複は FAIL、同値の重複は BLOCKED。完全な値で「支出合計 > 残高 − 予約」または「spender 別支出合計 > allowance」なら FAIL。
- **J12**: token 別予約、ETH（Ether）残高、未完了ガス費、ガス予備を要求し、欠測は BLOCKED。送信済み境界の各取引に gas limit と署名上限単価が無ければ BLOCKED。同じ送信元・同じ nonce で別 hash があれば合算せず BLOCKED。最大ガス費は `Σ gasLimit × maxFeePerGasWei` として本検査が導出し、自己申告値を受け取らない。予備が0以下、または `ETH残高 − 最大ガス費 − 未完了ガス費 < 予備` なら FAIL。
- **J05（境界〜hash 部分）**: 境界の試行識別子が投影された試行に無ければ FAIL。送信済み・未送信（送信前拒否）の試行に境界が無ければ BLOCKED。破棄された試行を送信済み境界にする、未送信境界に hash がある場合は FAIL。送信済み境界に hash が無い、hash が取引表に無い、同じ hash を複数境界が参照する、判断由来の取引がどの境界からも参照されない場合は BLOCKED。取引の world が入力と違えば FAIL。
- **J06〜J08 の引継ぎ**: 投影された判定が `BLOCKED` なら BLOCKED、`FAIL` なら FAIL、判定欠落も BLOCKED。
- **J09（1点）**: 包含ブロック番号が境界観測ブロック以下なら FAIL。
- **J14（1点）**: 補助送信を判断の境界が参照したら FAIL。由来 `unknown` の取引は BLOCKED。

判定語は `CONTRACT_OK_ON_SYNTHETIC` / `BLOCKED` / `FAIL` のみ。常に `g3Status: "BLOCKED"`、`liveRecorderVerified: false`。`provenance` が `SYNTHETIC` 以外なら内容を見ずに BLOCKED。欠測を0・`true`・空配列で補わない。入力を変更しない。金額は十進文字列で受け、BigInt で計算する。秘密や余分な本文を出力に転記しない。

## 3. 追加しても残る不足

実際の境界（送信直前の状態、送信待ち行列、Worker（戦略用の別スレッド）内で捨てた試行）の値を採取する記録器、予約・予備の実際の生成元、receipt 全文、実チェーン実体の同定、P01〜P07 の通信記録、J13 の全件数は未実装。今回の検査は人工入力の記録形式と整合を確かめるだけで、要件4全体は BLOCKED のまま。実装と実行結果は [g3/loader/README.md の要件4節](g3/loader/README.md#要件4の人工取引境界結合器2026-10-11追加) に記録する。
