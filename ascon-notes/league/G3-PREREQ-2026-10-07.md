## 2. オフライン交換記録と監査

追加した [revision_exchange.mjs](g3/chain/revision_exchange.mjs) は、既存 [revision_audit.py](g3/chain/revision_audit.py) とは別の、保存済み交換だけを扱う補助ツール。元の世界監査器、chain/gatesの実走経路、固定tool manifestは変更していない。

記録対象は `agents/cand.cli-timing.jsonl`、`agents/cand.llm.jsonl`、`agents/cand.jsonl` の3ファイルだけ。JavaScript Object Notation Lines（JSONL、1行1記録）の原文とSHA-256 digestを1つのJSONに保存する。出力は新規ファイルのみ、権限0600、上書き拒否。不正UTF-8、ログファイル自体のsymlink、親symlink経由のrunディレクトリ外への逸脱を拒否する。今回、一時ファイルで各拒否を発火させ、`invalid UTF-8 log` / `unsafe log path` を確認した。逸脱ケースは通常ファイルのleafと同一prefixの兄弟ディレクトリを使い、realpathの境界検査を確認する。標準出力にはraw/system/contextを表示しない。実ログは今回読まず、SYNTHETICだけで検証した。

監査はdigest、ログ終端・形式・切詰め、開始/応答/採否の件数、blockによる応答と採否の一意対応、時刻順序、model/system/context/rawの存在、versionの単調増加を確認する。標準 `parseRevision` / `compileExecutor` とログ内の既知version集合で採用・拒否・見送り・復帰要求の採否整合を照合する。今回、重複blockの `duplicate response block` FAILと、declined/revertedの偽装に対する `stock parse/compile disagrees with recorded outcome` FAILを確認した。`revertTo:0` / 採用済みの `1` / 未知の `99` とnull executorを使い、正常な見送り・復帰・未知version拒否もPASSとなる。これは保存済み応答と採否分類の検査であり、実際に要求先moduleへ復帰した証拠ではない。`compileExecutor` を呼ぶだけで生成executorは実行しない。Remote Procedure Call（RPC）やモデル・送信器は呼ばない。

交換検査の `status` / exit code はPASS=0、FAIL=1、BLOCKED=2。誤採用、digest改変、version不整合、時刻逆転などの確定不整合はFAIL。欠落、切詰め、未完了、採否の曖昧さ、rawがないprovider errorはBLOCKED。開始ログにはcall ID/blockがないため、開始との対応は順序による暫定対応に限る。cadence・実際のsetSource・経済安全性を認定しない。

**すべての結果に `g3Status: "BLOCKED"` と `liveRecorderVerified: false` を出す。** 世界監査hookの `counts/calls/evidenceSha256` プロトコルを提供せず、このツールのPASSを `gates.py revision-audit` の代わりに使えない。`parserSha256` は使用した `improve.ts` の識別であり、全依存の信頼済みmanifestではない。digestは保存後の変更検出であって、採取元の真正性の証明ではない。

provenance既定値は `UNVERIFIED`。テスト記録には明示的に `--synthetic` を付ける。`NATURAL` や `VERIFIED` の自己宣言は受け付けない。

### 実recorderに不足するもの

標準runtimeを静的確認したところ、`g3_decision_started` / `g3_action_attempt` / audit-frame出力はなく、`setSource` 呼出だけから後刻の完全なframeは復元できない。既存監査契約は以下を要求する。

1. `g3-audit.json` のworld/mode/case、期待件数、全対象ファイルdigest、開始ts/pidと実call blockのbinding。
2. 実setSourceの時刻・source hash・version・最初のdecision ID。`installedAtBlock` はcall blockであり代替不可。
3. noopとv0を含む全判断の実観測、worker generation、開始/完了時刻、read transcript、return/submit双方。
4. 実取引境界で取得した残高、spender別allowance、予約額、ガス費・予備、receipt、およびevents/blocksとの完全対応。
5. timeout時の実300秒制限、子終了、遅着適用なし、状態持越し・復帰時の証跡。

既存ログの後処理だけでは上記を生成できない。親側の外部収集で取得できるか、その完全性と標準runtimeの挙動・byte同一性を保てるかの実証が必要。**runtime変更なしで完全なlive recorderが成立するとは現時点では未検証**。収集できない項目を0・trueで補完せず、対応できる上流機構等の前提が整うまでBLOCKED。
