# r3・r3a・r3cの同一世界ログ比較 — 2026-10-08

r3a/r3cでは、r3より送信が増え、明示的なnoop（何もしない判断）が減っている。ただし、**Uniswap swapと二脚bundleの全体的な回復は小さく、inc-zeta並みの活動へ戻ったとは言えない**。回復費用を理由とするnoopは消えたが、元の発生は特定の市場局面に集中している。以下は保存ログの記述的な診断であり、ゲート判定でも、変更の因果効果の証明でもない。

## 比較対象と再現方法

[先行ログ比較](BEHAVIOUR-INCZETA-VS-R3-2026-10-07.md) は、r3の送信減少、明示noop増加、`recovery quote/cost not competitive` による見送りを報告した。[E5〜E7の実験説明](RESULTS-E1-E2-2026-10-07.md#2026-10-08追記e5r3ae6r3e7r3cの同一世界診断) による変更意図は次のとおり。これは比較対象の説明であり、本診断は戦略ソースの読解から挙動を推定していない。

- r3（E6、`ascon-zeta-r3`）：回復売却の見積価格・費用が不適合なら、早期にnoopを返す対照版。
- r3a（E5、`ascon-zeta-r3a`）：その早期returnをやめ、後続の通常裁定処理へ進む（フォールスルーする）研究版。
- r3c（E7、`ascon-zeta-r3c`）：r3aに加え、Wrapped Ether（WETH、ラップされたEther）の通常裁定行動を返す際、回復在庫への帰属を破棄する研究版。

inc-zetaは各run（実験実行）の比較基準席。同じregime（市場局面）とseed（乱数初期値）を世界キーとし、別runの候補同士、およびinc-zeta同士を対応させる。既存資料は同一Mac miniでの実行と記載しているが、本診断はホストへ接続して確認していない。同じ世界キーでも実行経路が同一とは限らない。

作業branchは `docs/behaviour-r3a-r3c`、確認したローカル `origin/main` は `65b1134030dccfb1c350f29203a43fd64cceb5f7`。リポジトリルートで実行したコマンド：

```sh
python3 -B ascon-notes/league/remote/behaviour_compare.py --same-world \
  --run r3 .scratch-logs/e6 ascon-zeta-r3 \
  --run r3a .scratch-logs/e5 ascon-zeta-r3a \
  --run r3c .scratch-logs/e7 ascon-zeta-r3c \
  --default-fee-wei 100000000 > /tmp/behaviour-r3a-r3c-2026-10-08.json
```

`--run NAME DIRECTORY CANDIDATE` は任意の名前・ディレクトリ・候補席idで繰り返し指定できる。ディレクトリは作業ディレクトリ相対で、`--root` 相対ではない。後に指定したrunから先に指定したrunを引く全組合せを出力する。`--same-world` なしのE1〜E4モードは維持する。

入力は各 `index.tsv`（Tab-Separated Values、タブ区切り表）、そのrun_dir欄を実験ディレクトリへ一度だけ連結した先の `summary.json` と両席の `agents/*.jsonl`（JavaScript Object Notation Lines、1行1レコード形式）。生ログは読取専用の `.scratch-logs/` にあり、リポジトリへ収録していない。上記JSON（JavaScript Object Notation）出力も一時ファイルで、cloneだけでは再生成できない。

`indexes` と `worlds[].summary_source`、`worlds[].seats.<席>.source` はパスとSecure Hash Algorithm 256-bit（SHA-256、入力照合用ハッシュ）を保持する。`worlds[]` には世界キー、index行、起動行、初回送信行、席別指標を保存する。`comparisons[]` は `run_a / run_b` を持ち、`paired_worlds[]` に世界別の差を保存する。本文表はこの出力を機械的に読み、表示のみ小数第6位へ丸めた。手数料のweiはgweiへ換算する（1 gwei = 1,000,000,000 wei）。

## 指標・対応差・flagの定義

- `submitted` は送信レコード数、`action_protocol/swap/uniswap` はactionTypeとprotocolが一致する送信数。送信増加は収益性の改善と同義ではない。
- `bundle_groups` は同一世界・席のbundleIdごとの組数。`bundle_tagged_tx` はbundleId付き送信数。`two_leg_submitted_groups` は送信2件かつbundleIndexが0・1の組。`one_record_bundle_groups` は送信1件の組であり、意図的な単脚化とは断定しない。二脚送信も両脚の採掘成功や原子性を意味しない。`unbundled_tx` はbundleIdなしの送信。
- `noop_records` は明示的なaction.type=noopのレコード数、`noop_rounds` はそのroundの重複除去数。今回両者は全世界で一致した。`noop_reason/recovery_cost` は理由文字列が厳密に `recovery quote/cost not competitive` の件数、`noop_reason/no_gap` は `no funded venue gap` の件数。送信のないブロックやlaunch監視を明示noopに加算しない。
- `includedTxCount / revertCount / unloggedTxCount` はsummary値。取込件数とrevert（実行の巻き戻し）件数を独立に掲載する。`event/submit_failed` は送信失敗であり、採掘後revertではない。`included_per_submitted` と `reverts_per_included` は件数比であり、取引ハッシュを追跡した成功率ではない。
- 手数料は送信ログの `priorityFeeWei`。defaultは指定した比較基準0.1 gweiと等しい値、bumpedはそれより大きい値。設定の実効値や競合への上乗せ理由を復元したものではない。`fee_5gwei_share` は観測値5 gweiの割合で、設定上限とは断定しない。
- Profit and Loss（PnL、損益）の単位はUSD Coin（USDC）。`pnlUsdc` と `netPnlUsdc` はsummary上の別フィールド。SIMPLIFIED T（簡易T）は各世界の全席のpnlUsdcから `50 + 10 × (P − 平均P) / 母標準偏差`（分散ゼロなら50）で求め、世界を等重みで平均する。**公式の後半エポック加重Tではない。**

世界wのrun間差を `D_candidate(w) = candidate_A(w) − candidate_B(w)`、対照を `D_control(w) = inc_A(w) − inc_B(w)` とする。表の平均は各Dの等重み平均。standard error（SE、標準誤差）はDの標本標準偏差を `sqrt(n)` で割る。runごとのSEを合成するのではなく、対応済みの世界差から計算する。対照は背景変動や候補置換による相互作用を含み得るため、候補差から自動的に差し引く補正量ではない。

件数カテゴリの不在は0、測定不能な手数料や時刻はnull。run間では候補A/B・inc A/Bの4値が揃う世界だけをその指標の両行で共通に使い、`n / missing` と世界別nullを出力する。今回全72席別指標・全3比較でn=36、欠測なし。実験内の候補−incの差は各世界の両席が揃う値から計算する。席間の初回送信時刻差は追加の関係指標として `aggregate.<run>.delta.first_submission_seat_ms` に保持する。

wins/nは、送信・swap・bundle活動・取込・損益では厳密な増加、noop・送信失敗・revertでは厳密な減少の世界数。活動についての「勝ち」は収益性や安全性の勝利ではない。同値はnに残し、勝ちに含めない。手数料分布や片脚bundleなど一意に望ましい方向のない指標は `—`（JSONではwins=null）。全指標の方向は `directions` に出力する。

**探索flagは、`abs(候補平均差) − 2×候補SE > max(abs(対照最小差), abs(対照最大差))` を厳密に満たす場合だけ付ける。** n≥2が必要。平均差の大きさから2 SEを引いた参考量が、対照の観測範囲全体の最大絶対値を超えるという保守的なルールである。対照の外れ値や局面への集中に敏感であり、検出力を保証しない。2 SEは信頼区間・有意水準の主張ではなく、この記述ルールの余裕幅。世界間独立を保証せず、仮説検定・多重比較補正は実施していない。出力は `flag_rule`、各指標の `candidate_margin / control_radius / flag`。**今回、全3比較ともflagは0件だった。** これは差がゼロという結論でも、同等性の証明でもない。
