# Worker recorder prototype (2026-10-14)

This measurement build was exercised on the existing offline fixture runner. No acceptance result is inferred. The only verdicts are `CONTRACT_OK_ON_SYNTHETIC`, `BLOCKED`, and `FAIL`; every result has `g3Status: BLOCKED` and `liveRecorderVerified: false`.

## What the prototype records

- `g3/loader/worker-capture-preload.mjs` resolves and checks the pinned `strategyWorker.ts` SHA-256 and exact source insertion anchors, transforms that source in memory, and records callback entry, read calls and completion, submit attempts, result/error posts, and callback finalization. The worker-module match is normalized to an absolute path. A preload inherited by a non-target worker with an absent or malformed `__g3WorkerCapture` marker stays inert, including skipping the transform hook. Every numeric generation observed in parent or worker records must have a matching create; each created generation needs exactly one hook record on the same worker thread as its callbacks. It does not edit upstream source files.
- Each read proxy and submit ordinal counter is created for one callback and closes over that callback's context. A delayed read completion therefore retains the decision ID that started it, including when callbacks overlap. Ordinary member calls use the underlying client's original receiver; detached or explicitly rebound calls forward that call receiver. Function wrappers are cached by target object, callback context, and property, so repeated reads of an unchanged method return the same wrapper. The wrapper references differ from the raw client's references (`client.fn !== proxy.fn`), and the proxy itself has a different identity from the underlying client.
- Native Promises are observed without replacing the returned Promise. Other thenables pass through untouched; the recorder does not read or call their `.then` property. Synchronous non-Promise return values are recorded as immediate read completion.
- Read argument digests use a descriptor-based canonical form with bounded output, not bounded computation cost. It does not invoke property getters or `toJSON`. The digest is a shape/value summary: accessors are represented as accessors, arrays and object keys are capped at 32 entries, nesting is capped at four levels, and bigint values are represented by type. It is not a full argument-value digest.
- The preload appends a final `capture_summary` for the parent capture stream and each instrumented worker. Worker write count and gap state use a shared two-counter buffer so the parent can append the worker's final record after thread exit. A failed append attempts a best-effort `capture_gap`; the summary also retains `gap: true`. The audit checks contiguous integer sequence numbers, one final summary per captured stream, matching pre-summary record counts, and `gap: false`. The parent capture stream is a separate logger from the offline probe's parent records; the latter continue to be checked by the probe's own audit. A failed write, missing middle/last row, or missing summary blocks the result. Sink paths under `example`, `runtime`, `sdk`, `lib`, or `core`, including symlinked path components, are refused.
- `g3/loader/worker-capture-audit.mjs` joins parent and worker decision IDs, checks capture-stream sequence continuity before order comparisons, requires the pinned digest on each worker hook record, and enforces callback order: entry, reads/submits, terminal result/error, then `finally`. The result/error terminal stores the total submit-attempt count, which is checked against the callback's attempts even if attempts and parent receipts are deleted together. Every submit attempt must have a boolean `active` value; an inactive attempt before the terminal fails, and any submit after the terminal fails. Active attempts require both a parent receipt and a `worker_submit_identity` row with matching worker decision ID, generation, action hash, and ordinal. Only the raw parent receipt is also joined to the parent decision ID. Receipt array order is not used to infer identity. Expected generations are checked against the independent parent-generation records.
- `g3/tests/worker-capture-controls.test.mjs` pins the measurement CLI to Node v24.13.0 and asserts the real Node runtime identity rather than deriving the expected version from whichever binary ran the test. It covers callback ordering, submit identity mismatches, missing/unsafe joins, sequence/summary checks, phantom generations, hook/thread binding, missing counts/identity, write failure, inactive/late submits, Promise/thenable behavior, protected sinks, proxy behavior, concurrent callbacks, non-target workers, and mutation controls. The real fixture runs both the independent probe and capture preload. Parent probe `worker_submit` receipts hash the received structured-clone action and assign a per-worker-decision ordinal; an end-to-end synthetic audit checks one-to-one agreement with the separately captured identity rows. This closes the earlier missing-raw-receipt-field blocker for supported action shapes, but remains synthetic measurement evidence. The unhandled-rejection control records a known behavior difference described below. The read-proxy positive control feeds observed proxy events through the audit.
- The digest test changes only the expected hash in a temporary preload copy and compares it with the unchanged real worker file. A separate synthetic control changes a recorded digest. Neither alters `strategyWorker.ts`.
- `g3/loader/worker-capture-mutation.mjs` removes one audit guard per mutant in a temporary module under the OS temp directory. Each mutation needle must occur exactly once, and its evidence checks the expected verdict with the selected guard removed. The earlier round-4 run reported `MUTATION_SUMMARY killed=21/21`; the current handoff cycle adds three independent guards, and mini reports `MUTATION_SUMMARY killed=24/24` in `~/ascon-control/logs/worker-r6-mutations.log`.

`CONTRACT_OK_ON_SYNTHETIC` means only that the supplied synthetic evidence passed these checks. It is not live recorder verification. Its `limitations` field explicitly marks the bounded submit-action digest, the unjoined return digest, Promise rejection observer behavior, and unproven timing/live equivalence.

## What remains unproven

The prototype does not establish coverage or behavior in botMain, a submission environment, a real chain, or every supported Node/tsx version. It does not establish independently complete expected counts, trustworthy parent disposition evidence, durable or tamper-resistant storage, or timing safety. The existing offline fixture and synthetic controls are the only exercised environments. The parent capture stream and worker capture streams have their own sequence and summary checks; the offline probe's independent parent stream has no recorder summary and remains outside this recorder audit's integrity check. The real fixture's raw submit rows also lack ordinal and hash fields, so that trace is deliberately blocked rather than promoted to an end-to-end positive audit.

The digest mismatch control proves that the pin check rejects changed expected bytes in a disposable copy. It does not show that a live deployment uses this preload or these exact bytes. Hook absence is blocked by an audit control that removes the observed hook marker while preserving the rest of the fixture trace.

## Measurement-build behavior differences and interference risk

This is a measurement build, NOT the submitted artifact; equivalence is unproven. Proxy method identity is stable for a callback while its underlying function target is unchanged, but function metadata differs, wrapper references differ from the raw client's (`client.fn !== proxy.fn`), the proxy has a different identity from the original client, and callback proxies are distinct. Ordinary member calls are mapped back to the original client receiver; detached or explicitly rebound calls keep their invocation receiver. Proxy lookup and user-defined Proxy traps can still be observable. Descriptor inspection avoids ordinary getters and `toJSON`, but a user-supplied Proxy can run its own `ownKeys` or descriptor traps. Canonical digest output intentionally omits some values and must not be treated as exact argument evidence. For objects and TypedArrays, all own descriptors are enumerated and enumerable keys sorted before the 32-key output cap; large inputs can therefore impose unbounded synchronous measurement overhead. No timing-safety claim is made.

Promise observation uses `util.types.isPromise` and attaches fulfillment/rejection handlers with `Promise.prototype.then.call` while returning the original Promise. The rejection observer marks the original Promise as handled and therefore suppresses `unhandledRejection` in this measurement build. Observing rejection settlement without attaching such a handler would change behavior another way or is not available through the Promise API. It can change scheduling and timing. Non-native thenables are deliberately not subscribed to, so their settlement is not captured. A read or submit after the callback terminal is classified as `FAIL` (`callback_activity_after_terminal`); this can reject legitimate fire-and-forget work and is a deliberate strict audit choice. The injected `callback_finally` record is emitted BEFORE stock code sets `active = false`, so the recorder observes that flag being cleared slightly later than stock. The in-memory transform bypasses the stock tsx load chain and directly transforms TypeScript with esbuild. The target worker's `workerData` gains `__g3WorkerCapture`, which carries the sink path and shared counters; strategy context is not unchanged. Extra workerData, shared counters, synchronous `appendFileSync` before stock post/read handling, hashing, and parent-side exit summaries add startup, CPU, I/O, and memory overhead and can shift event order or consume deadline margin. The parent `worker_submit_identity` listener runs before the stock runner's message listener; its synchronous hash and write run before stock message handling. A write failure can emit an extra gap attempt and affect sequence continuity; a blocked or unavailable sink can omit both gap row and summary. Recorder failures can alter timing or terminate the measurement run. The real late-submit control uses an unawaited Promise chain in the real worker callback; timers remain unavailable to the strategy VM.

The recorder does not write RPC headers, keys, tokens, complete actions, or complete read arguments/results. Hashes, types, sequence metadata, and decision identifiers remain measurement data and can still disclose behavioral patterns.

### Codex self-review follow-up (2026-10-15, r10)

The r9 self-review found that the bounded action canonicalizer still hashed truncated arrays/objects, deep values, cycles, and lossy value markers. Distinct submitted actions could therefore share a digest that the join treated as identity. The r10 candidate now returns no digest when canonicalization is incomplete or unsupported (including accessor/cyclic/uninspectable values, values beyond the collection/depth bounds, non-plain built-in objects, functions/symbols/BigInts, and non-finite or negative-zero numbers). Focused fake-only regressions cover these cases. This prevents the recorder from asserting an incomplete identity; it does not expand the supported action schema or prove live worker/parent equivalence. Unsupported cases must remain BLOCKED. The earlier bounded read-argument shape digest remains descriptive evidence only.

## Handoff improvement cycle (2026-10-15 JST)

Independent Claude and Grok reviews found that worker-originated rows do not have the parent's decisionId. Submit joins now use generation, workerDecisionId, ordinal and action digest on the worker side, retaining the parent receipt-to-post decisionId check. Parent receipt ordering and entry-before-terminal ordering for empty callbacks are explicitly checked. Synthetic worker rows no longer invent a parent decisionId.

A forced-interleaving mini control demonstrated a recorder race: terminating the worker after append but before the shared counter increment produced a summary that duplicated the last written sequence (recordCount 2 although callback_entry sequence 3 was on disk). The recorder now reserves the sequence in shared memory before append. Termination after the write keeps that sequence in the summary; termination before completing a reserved append leaves a detectable gap. This is not evidence that every possible lost write is observable.

Four new controls were red on the previous prototype and green after these fixes on mini; logs: `~/ascon-control/logs/worker-r5-red.log` and `worker-r5-green.log`. The controls total 49; two new isolated auditor mutants cover the added ordering guards. Final full-suite counts are pending in `~/ascon-control/logs/final-r6/` and are not inferred from the four-control result.

The `actionSha256` currently uses the same bounded descriptor summary as read arguments. It is not a complete serialization identity: fields past the cap, deep structures and some value types can collide. A mini Node v24.13.0 `structuredClone` probe confirmed that an own enumerable `undefined` property is preserved and a function-valued property throws `DataCloneError`, so those proposed examples do not establish hash skew for a posted action. The probe also confirmed that cloning invokes an enumerable getter and turns it into a data property. A module-mode worker control reproduced this boundary: the worker observes the accessor before `postMessage`, while the parent hashes the cloned data property. Accessor-bearing values in the inspected bounded summary now produce no action digest, and the auditor returns `BLOCKED: submit_action_hash_unsupported` instead of treating the missing digest as a contradiction. Plain-value hash contradictions still return `FAIL`. This is a bounded unsupported-shape guard, not full action identity; omitted/deep values and live equivalence remain unproven. `resultSha256` is recorded before the worker posts its result, but the available parent probe does not provide a comparable result digest, so the worker return hash is not joined to the parent result or delivery. Neither hash establishes action or return-value equivalence. Real identity and full live acceptance remain unproven, even if synthetic multiset joins pass. Concurrent append writers and summary integrity remain limited to tested cases; fail-closed audit results do not prove durable or tamper-resistant storage.

The frozen mini run passed 49/49 Node controls, 16/16 existing loader probes and `bun run typecheck`. A further malformed-row guard has its own RED→GREEN control and a 24th isolated mutant. The latest full control count is 50, with its final frozen run still pending. Non-target malformed JSON rows now return `BLOCKED: record_shape_invalid` rather than throwing. Real fixture expected generations are taken from the independent probe's worker_create rows, not capture parent_generation rows; synthetic expectations remain explicitly supplied.

Bun v1.4.2 lacks Node's registerHooks. The test harness now resolves the actual Node child binary when the outer runner is Bun, retaining the same measurement runtime and assertions. With the existing child fixture's 90000ms bound also applied to the outer Bun case, `bun test --timeout 90000 .../worker-capture-controls.test.mjs` passed 49/49 before the malformed-row case was added. Default Bun outer cases expired at5000ms while the full offline fixture normally takes about8–9seconds; no product decision timeout was changed. Latest 50-case verification remains pending. The removed parent decisionId control is an old-auditor RED comparison; after the base fixture adopted the real row shape, its delete operations are no-ops and the clean positive also guards that shape.

One mutation expectation was corrected after the identity repair: deleting the one-to-one guard now genuinely permits CONTRACT_OK_ON_SYNTHETIC, whereas the earlier expectation incorrectly relied on a second FAIL. The good input must reach submit_identity_contradiction, and the isolated mutant must escape it. Both verdicts are now asserted; this does not weaken the auditor.
