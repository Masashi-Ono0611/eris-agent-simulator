指定の3ファイルを読み、既存戦略と弱点レジームを把握したうえで、ギャップ裁定の再パラメータではない防御機構を1つ提案します。# 仕様: ストレス検知ゲート付き在庫凍結（Toxic-Gap Circuit Breaker）

## 1. 仮説（1つ）

**仮説:** crash / whale で多数が弱い主因は、ギャップ裁定の閾値・サイズそのものではなく、「急変直後の大きな乖離を一時的ミスプライスと誤認して取りに行き、不利な在庫を抱えたまま競合に負け続けること」である。`decide()` が観測できる公正価格の短窓変動と乖離の持続性からストレス状態を推定し、その間は **裁定コアを止めずに「在庫を増やす方向の新規エントリだけを禁止／縮小」** すれば、裁定コアの平時利益を保ちつつ相対 T の下振れを抑えられる。

根拠: STRATEGY-CARDS は全員が同一の WETH/WBTC 公正価格ギャップ裁定を核とし、上位でも whale が弱点（opus-1 45.15、sonnet-1 48.96、venue-arb 49.79、inc-zeta 49.45、grok-1 49.36；`report-u1m.md`）。crash は分散が大きく、inc-zeta 58.82・venue-arb 57.24 は強い一方 opus-1 47.75・grok-1 47.25・clean-arb 42.37 は弱い。ZETA2-REGRESSION は「保守的利益が非正なのにゼロ優先手数料で大量送信→約定品質劣化→約 −13 T」を示し、**不利な状況で薄い入札のまま動くことの破壊力**を測っている。

## 2. 利益の仕組み（なぜ他から取れるか・何を見るか）

相対スコア T では、弱いレジームで他者が損する局面を「負けない」ことが順位に効く（上位5体は平均 T が約1以内・CI に0を含む；`report-u1m.md`）。本機構は新しい裁定経路ではなく **防衛**:

- **見る資産:** WETH・WBTC の公正価格（既存コアと同じ基準点）、各 venue（Uniswap / Balancer / Curve）の提示価格と深さ、自口座の WETH/WBTC/USDC 残高、mempool 上の競合 tip（既存入札入力）。
- **取るもの:** ストレス時に他者が追う「急拡大ギャップの安い側」を意図的に見送る。結果として、クラッシュ中の買い増し・ホエール同方向の追従で増えた不利在庫を相対的に少なく保つ。
- **捨てないもの:** ストレス解除後、およびストレス中でも **在庫を減らす方向**（過剰 WETH/WBTC の公正価格への回帰売り、現金化）のギャップ裁定は従来どおり実行し、優先手数料も利益連動で維持する（zeta-2 のゼロ入札回帰を繰り返さない）。

## 3. 予測（方向・大きさ・効く／効かないレジーム）

- **方向:** 平均 T を大きく押し上げる主張はしない。狙いは **worst-regime T（特に whale・一部 crash）の底上げ** と、その結果としての相対順位の安定。
- **おおよその大きさ（予測・未検証）:** whale で上位勢が ~45–50 に固まる中、防衛が効けば **同条件で +2〜5 T 程度の worst 改善**を期待する水準（clean-arb の whale 61.89 は別構造の偶然寄りで再現目標にしない）。平均 T への寄与はレジーム等重みならその 1/12 規模。
- **効きやすい:** whale（急大口フロー）、crash（公正価格の急落局面で「安く見える買い」を踏むプレイヤー）。
- **効きにくい／害になりうる:** cex-drift（venue-arb 73.70 が示す持続的 venue 乖離）、informed-flow（inc-zeta 64.26）、launch / cdp-incident（opus-1 の専門モジュールが勝つ局面）。ここでゲートが過敏だと機会損失。calm では発火しない設計が必要。

## 4. 失敗条件（これが観測されたら仮説は誤り）

1. ストレス判定がオンのブロック割合が高い（例: 全決定の **>25%**）のに、whale/crash の T がベースライン（同一コア・ゲート無し）と **統計的に改善しない**（同 seed ペア差の中央値が ≤0）。
2. ゲート発火中に「在庫増加を禁止した」にもかかわらず、最終 WETH+WBTC の公正価値エクスポージャがベースより大きいか同程度で、かつ worst T が悪化。
3. cex-drift / informed-flow でベースより **ΔT ≤ −3** が複数 seed で再現（平時の持続ギャップまで毒性と誤判定している証拠）。
4. ゼロ／サブデフォルト優先手数料の送信比率が有意に増え、ZETA2 と同様の「後追い・悪化価格」パターン（同機会で後の txIndex・adverse bps）が再発。

## 5. 必要な観測（decide() の合法情報のみ）

レジーム名・seed・将来ブロックは使わない。

- **現在:** 各 AMM の WETH/USDC・WBTC/USDC（および既存コアが使うペア）の実行可能気配、手数料 bps、プール深さ、自残高、競合 priority fee。
- **過去（エージェント内部状態・直近 K ブロック分のみ）:**  
  - 公正価格 \(F_t\)（既存の fair 計算）の対数リターン \(r_t=\ln F_t-\ln F_{t-1}\)。  
  - 最良ギャップ \(g_t=|\text{venuePrice}/F_t-1|\) とその符号（買いで埋めるか売りか）。  
  - 同一方向ギャップが連続したブロック数 \(P\)（持続カウンタ）。  
  - 任意: 直近で観測した mempool の同方向想定サイズ合計（プロトコルが渡す範囲に限る）。
- **導出フラグ `stress`:** 例えば  
  - \( \mathrm{RV}_{8}=\sqrt{\sum_{i=0}^{7} r_{t-i}^2} > 80\,\mathrm{bps}\)（8 ブロック実現ボラ）、**または**  
  - \(g_t > 150\,\mathrm{bps}\) かつ \(P \le 2\)（急拡大・未平均回帰）、**または**  
  - 単ブロック \(|r_t| > 40\,\mathrm{bps}\)。  
  数値は STRATEGY-CARDS の入口（10–60bps）より十分大きく、「通常アーブ」と「急変」を分けるための初期案であり、ファイル上の最適値ではない（不確実）。

## 6. 実装の概要（モジュール・数値案）

**追加モジュール `stressGate`（専門モジュール扱い・裁定コアの前段）:**

1. 毎 `decide()` で上記から `stress ∈ {0,1}` を更新。ヒステリシス: ON 後は RV が 50bps 未満かつ \(P\ge 4\)（ギャップが縮み持続）になるまで OFF しない（チャタリング防止）。
2. **`stress=0`:** 既存ギャップ裁定をそのまま（推奨ベースは利益連動入札を持つ系: inc-zeta 型＝競合+0.1 gwei・利益の最大30%、または opus-1 型）。**入札式は触らない**（ZETA2: 入札入力の保守化が 40.81% ゼロ入札を生んだ）。
3. **`stress=1`:**  
   - **入口:** 在庫を増やす側のレッグは、追加で **+100 bps** の実効閾値（例: 元が fee+50bps なら実質 fee+150bps）を要求。満たさなければ noop。  
   - **サイズ:** 増やす側は `min(残高の 2.5%, 深さの 5%)` に硬キャップ（STRATEGY-CARDS の下限 2.5% に合わせ、上限 25% を使わない）。減らす側は従来の 2.5–25% 可。  
   - **入札:** 残す注文は必ず `max(競合+0.1 gwei, 利益シェア上限内)`。保守利益 ≤0 なら **送らない**（zeta-2 variant C と同趣旨: ゼロ入札送信禁止）。  
   - **撤退:** 公正価格から見て過剰な WETH/WBTC（初期比または目標帯外）は stress 中でも売却可。ただし「買った直後の無条件全量売り」（ZETA2 が増幅要因とした 0.1 gwei sweep）は、stress 中は **追跡した増加分のみ・かつ利益または在庫帯復帰があるときだけ**に制限する案（新規設計実験；レビュー修正の巻き戻しではない）。
4. **5 s:** ゲートは O(1) のリングバッファ更新のみ。AMM 見積もり回数は増やさない（既存候補の後処理フィルタ）。

## 7. 安全な出口と最悪ケース

- **資産損失上限（意図）:** stress 中の新規リスク増加を残高 2.5%／深さ 5% に閉じる。1 ブロックあたりの追加エクスポージャを、初期 8 WETH / 0.4 WBTC 規模に対して小さく保つ（絶対 USDC 上限は公正価格依存のため固定ドル額は断言しない）。
- **5 秒締切:** 追加計算は定数時間。タイムアウト気味なら `stress` を前回値のままにし、増やす側だけ noop（fail-closed）。
- **無効注文:** サイズ ≤0、残高不足、保守利益 ≤0、バンドル片足資金不足は送らない（zeta-2 の funding precheck は維持方向）。GMX 等を足さないため grok-1 型の `sizeDeltaUsd must be positive` クラスは持ち込まない。
- **最悪ケース:** 誤検知で cex-drift の持続ギャップを逃し、venue-arb に大きく負けうる。その場合は §4-3 で仮説破棄し、閾値を上げるかゲートを whale 寄り特徴（単発巨大 \(g_t\)+低 \(P\)）に狭める。

## 8. 既存の戦略との違い

| 近い既存 | 共通点 | 本機構の新しさ |
|---|---|---|
| sonnet-1 | 防御・在庫帯 ±20%・最悪エポック回避志向 | 在庫帯の常時制約ではなく、**価格経路・ギャップ持続から一時モード切替**。閾値 60bps の再調整ではない。 |
| opus-1 | 在庫を基準へ戻す | エッジがあるとき動く在庫統制に加え、**ストレス時は増やす側を構造的に禁止**。7 モジュールの新利益源は増やさない。 |
| grok-1 | 防衛的 | GMX ショートは使わない（不正注文リスクと別利益源を避ける）。スポット在庫のゲートに留める。 |
| venue-arb / clean-arb / multi-arb | ギャップ核 | コアの 10–60bps や 2 レッグ優先をいじらない。**観測ゲートという別レイヤ**。 |
| zeta-2 の教訓 | — | 安全のための保守会計を入札に混ぜてゼロ入札化しない。防衛は「送らない／小さくする」で表現する。 |

## 9. 因子分類

**主分類: 観測による制限（新規機構）** + 副次的に **在庫**（増やす側の禁止）と **サイズ**（stress 時キャップ）。  
入口閾値の常時再パラメータ、入札シェアの変更、Liquity/launch/GMX 型の専門利益モジュール追加には当たらない。ギャップ裁定コアの数式は平時そのまま残す。
