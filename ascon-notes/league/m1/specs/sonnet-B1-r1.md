**仕様 B1: トレンド連動の在庫目標（ドローダウン・スロットル）**

読んだのは STRATEGY-CARDS-U1.md、report-u1m.md、ZETA2-REGRESSION.md の3ファイルだけです。他のファイルは読んでいません。数値の出所は文中の括弧で示します。性能は主張しません。

## 1. 仮説（1つ）

crash レジームでは、裁定の利益よりも、手持ちの WETH/WBTC の時価変動が相対スコアを左右している。そこで「直近の下落が深いときは、在庫の目標水準を初期在庫より下げ、在庫を増やす方向の裁定レッグを控える」という状態依存の規則を足す。これで crash の下振れが縮み、他のレジームでの損失が小さければ、全体の T は改善する。

根拠と、確かでない点は次のとおり。
- crash は多くのプレイヤーの最悪レジームである。最悪レジームが crash なのは astra-1 43.67、astra-2 43.04、clean-arb 42.37、grok-1 47.25 の4体。whale が最悪なのは opus-1 45.15、sonnet-1 48.96 の2体で、これも同じ種類の弱さかもしれない。
- crash の seed 201 と 203 では、inc-zeta に対する差 ΔT がほぼ全員で大きく負になる（例: astra-1 -21.61 と -28.89）。seed 202 は正が多い。つまり seed 依存が強く、1回の u1m だけでは確かでない。
- ZETA2-REGRESSION は、P が在庫に依存することを示している。最終 WETH は 0.18〜8 WETH とばらついている。noop の P も、calm/202 の +443.66 から informed-flow/201 の -508.55 まで動く。ただし、報告書は「終値の時価と一部のプロトコル評価は P に残る」と書いている程度で、スコアが USDC 換算の時価にどこまで依存するかは確認できていない。
- 反証側の証拠もある。grok-1 は増えた在庫分だけ GMX でヘッジするが、crash は 47.25 で首位ではない（inc-zeta 58.82、zeta-2 60.03、venue-arb 57.24）。ただし grok-1 は基礎在庫をヘッジしないため、本仕様の検証にはならない。

## 2. 利益の仕組み

これは新しい利益源ではなく、損失を抑える防御である。裁定の核は温存する。

- 見る資産と venue は WETH と WBTC。Uniswap、Balancer、Curve の価格から参照価格 p_t を作る。3 venue の WETH/USDC 実効価格の中央値とし、WBTC も同様にする。
- 下落が続いている間は、(a) 基礎在庫の一部を、高値側の venue への売りレッグとして USDC に替える。(b) 売った分を買い戻す側の「安値買い」裁定レッグは閾値を上げて控える。売りレッグは、核がもともと出す「高い venue で売る」注文と同じ向きなので、追加コストは小さいはずである。
- 他の参加者から取るというより、続落時の在庫評価損を取らない形で、相対的に差をつける。
- whale は狙わない。whale の差は seed 間で符号が割れており（seed 202 は大半が -20〜-32、seed 201 は +20 前後）、在庫の時価だけで説明できるか不明である。clean-arb だけは seed 203 で +30.21 と、他と挙動が違う理由が不明である。

## 3. 予測（方向・大きさ・どのレジームか）

- 方向は crash で T が上がり、spike と cex-drift の上昇局面で T がわずかに下がる、という見立てである。大きさの根拠はない。crash で +0〜+5 T、他の 11 レジームの合計で -2 T 以内を目安とするが、これは見積もりであって測定ではない。
- トップ5が互いに約 1 T 差で CI が 0 を含む（opus-1 +0.63 [-2.95, 4.20] など）ため、全体の T の変化は検出できない可能性が高い。
- 効きにくい場面は、下落が数ブロックで反転する急落（whipsaw）と、緩やかな下落で閾値に届かないケースである。
- crash の実際の価格経路（急落か漸落か）は、読んだ3ファイルに載っていない。だから大きさの予測は低確信である。

## 4. 失敗条件

次のいずれかが観測されたら、仮説は誤りである。
1. 参照価格が24ブロックで -3% 以上下がった局面を全 crash 走行で集計し、その後24ブロックで更に下がる割合が50%未満である（平均回帰が優勢）。
2. 既存の上位プレイヤーと、本機構を足したものを同じ seed・同じロスターで比べ、crash の T が改善しない。または 3 seed 全てで悪化する。
3. crash 以外の 9 レジームの平均 T が 0.5 T 以上悪化する。
4. 通常レジーム（calm）で、トリガーが全ブロックの 15% 超で発火する。
5. 売却と買い戻しの往復で、手数料込みの実損が合計 0.25% を超える走行が複数ある。

## 5. 必要な観測（decide() が見る合法な情報だけ）

- 各ブロックで取得済みの 3 venue の WETH/USDC と WBTC/USDC の価格。追加の RPC 呼び出しは不要である。
- 自分の WETH・WBTC・USDC 残高と、初期ブロックで観測した初期残高（基準点）。
- 過去60ブロック分の p_t の履歴。ブロック間の状態は agent.ts が持つ構造に載せる。ZETA2-REGRESSION によれば、全 tape で判断ブロックの欠落はなかった（362 ブロック連続）。
- 現在のブロック番号と、エポックの残りブロック数（最終 12 ブロックの凍結用）。
- レジーム名・seed・将来の価格は使わない。

## 6. 実装の概要

追加するモジュールは `trendState`（状態計算）と `shedPlanner`（売却計画）の 2 つで、核の delta ロジックの前段に置く。数値は全て初期案であり、根拠のあるチューニング結果ではない。恣意的な値だと明記する。

**トレンド状態（0〜2）**
- dd24 = p_t / max(p_{t-24..t}) − 1、dd60 = p_t / max(p_{t-60..t}) − 1。
- レベル1に入る条件は dd24 ≤ −3%。レベル2に入る条件は dd60 ≤ −6% または dd24 ≤ −5%。
- 下げる条件はヒステリシスで、24ブロック高値の 1.5% 以内まで戻る、または最安値の更新が 36 ブロック止まる、のどちらか。1段ずつ戻す。
- 最終 12 ブロックはレベルを変更しない。

**目標在庫**
- レベル0は初期在庫の 100%、レベル1は 70%、レベル2は 40%。WETH と WBTC に同率を適用する。
- 初期在庫は 8 WETH と 0.4 WBTC（ZETA2-REGRESSION の manifest）。ただし他のレジームで同じかは未確認。

**売却の実行**
- 1ブロックにつき売却注文は1件まで。1件のサイズは (現在在庫 − 目標在庫) の 25% と、池の深さの 0.15%（opus-1 の深さ連動を参考にした）の小さい方。
- 売りは、3 venue のうち p_t より最も高い venue を選ぶ。その venue が参照価格より (手数料 + 10 bps) 以上安いなら見送る。
- 12 ブロック超で目標に届かない場合は、実行コスト 25 bps を上限として強制的に進める。
- 在庫を増やす向きの裁定レッグは、レベル1で閾値を 1.5 倍・サイズを 0.5 倍、レベル2で閾値を 2 倍・サイズを 0.25 倍にする。売り方向のレッグは変えない。

**入札**
- 売却注文の優先手数料はゼロにしない。下限は既定の 0.1 gwei で、競合手数料 + 上乗せ（opus-1 と同じ ×1.2 + 1 型）まで上げ、上限は 2 gwei とする。
- 根拠は ZETA2-REGRESSION である。ゼロ入札の注文は 85/87（calm/201）が後順位で約定し、中央値 12.81 bps 不利だった。冗長な入札を避けるのではなく、損をしないために最低限は入札する。

## 7. 安全な出口と最悪ケース

- **損失の上限（資産）**: 売却は初期在庫の最大 60% まで。実行コスト上限は 25 bps で、約 28.8k USDC 分を売っても約 72 USDC である。
- **機会損失の最悪例**: 下落後に急反転して +5% 戻ると、売却済み分の逸失は約 1.2k〜2k USDC になりうる（4 WETH×3000×5% + 0.2 WBTC×60000×5% ≒ 1.2k。買い戻し側の遅れを入れると上振れする）。これは 1 走行の u1m 内の P の変動（数百〜数千 USDC）と同程度で、小さくはない。この点が最大の弱点である。
- **5 秒締切**: 追加計算は 60 要素の履歴と簡単な算術だけで、RPC を足さない。状態が欠けたらレベル0に戻して核だけで動く。
- **無効注文の防止**: サイズが 0 以下・ダスト未満なら出さない（grok-1 の `sizeDeltaUsd must be positive` の教訓）。残高と手数料用の残りを確認してから出す（zeta-2 の資金事前チェックと同種）。最小受取額は見積から決める。
- **エポック終盤**: 最終 12 ブロックは新規にレベルを変えず、既存の売却計画は維持する。

## 8. 既存の戦略との違い

- 最も近いのは opus-1（在庫を基準点へ戻す）と astra-1（在庫への罰則、最大 60 bps）。どちらも目標は固定、または乖離に対する価格上の罰則で、トレンドで目標を動かしてはいない。
- grok-1 は増えた分だけ GMX でショートし、基礎在庫は売買しない。本仕様は基礎在庫を現物で減らす点が違う。GMX は使わず、GMX 側の巻き戻しの不正注文（agent.ts:455-461 付近）の分岐も持たない。
- inc-zeta と zeta-2 には、無条件の「余剰 WETH 売り」（0.1 gwei）がある。ZETA2-REGRESSION は、これを cdp-incident での損失の増幅要因として計測した（WETH 買い→翌ブロック売りの現金損益: zeta-2 -4,045.01、inc-zeta -1,048.36）。本仕様の売りは、条件付きで、入札もゼロにしない。
- 新しい点は、(1) 目標在庫が時間変動する、(2) 買いと売りで閾値を非対称にする、の2つ。

## 9. 因子分類

新機構である。ただし、既存の因子との接点は次のとおり。
- 在庫: 目標水準がトレンド状態で動く。
- 入口閾値: 在庫を増やす向きにだけ 1.5〜2 倍。
- 観測による制限: レベルの計算が過去 60 ブロックの価格履歴に依存する。
- 入札: 売却注文の最低入札を設ける。
- 専門モジュール: 該当しない。

不確かな点が3つある。(a) crash の価格経路。(b) P がどこまで時価に依存するか。(c) 初期在庫がレジームごとに同じか。この3つは、読んだ3ファイルからは確認できていない。実装の前に、crash の 3 seed の価格系列と P の定義を確認する必要がある。
