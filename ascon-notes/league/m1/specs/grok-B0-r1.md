指定の3ファイルだけを読み、B0向けの裁定コア改善案を1本に絞ります。# B0 仕様: 競争可能入札ゲート付き裁定コア

## 1. 仮説（1つ）

同一の WETH/WBTC 公正価格ギャップ裁定では、**入口を通した単脚注文を、競合が払う優先手数料に届かない tip（特に 0）で出すと、同一ブロック内で後順位・悪化約定になり、相対 T を失う**。  
根拠: `ZETA2-REGRESSION.md` で zeta-2 は提出の **40.81% が tip=0**（inc-zeta は 0 件）、マッチ成功注文は大半が後の txIndex・悪化価格（例 calm/201: 85/87 が後順位、中央値不利 **12.81 bps**）。平均 T 差 **−13.28**（CI −17.81〜−8.80）。選択閾値は維持したまま入札予算だけが保守化され、非正の保守エッジでも注文を送る実装だった。

## 2. 利益の仕組み（なぜ他の参加者から取れるか・どの資産/venueの何を見るか）

利益源は変更しない: **WETH / WBTC** の公正価格からの乖離を **Uniswap・Balancer・Curve** 間で取る（`STRATEGY-CARDS-U1.md` 共通核）。  
相対で取る経路は「ギャップ発見」ではなく**同一ギャップ上の約定順位と fill 品質**。`report-u1m.md` の行動指標では tip 連動・利益連動入札を持つ系統（inc-zeta・opus-1）が上位帯、固定入札の multi-arb は平均 T **39.45**。ただし venue-arb は固定入札で首位のため、「入札万能」は断定しない。狙うのは **zeta 回帰で実測された「届かない tip で同じ機会に参加する」弱点**を止め、届くときだけ競争的に乗る点。

## 3. 予測（方向・おおよその大きさ・どのレジームで効くか/効かないか）

- **方向**: tip=0／劣後約定の削減 → 同一ギャップでの fill 改善。性能の数値主張はしない。  
- **効きやすい**: 複数エージェントが同ギャップに同時参加する局面（`ZETA2` の calm・informed-flow・vuln で同機会マッチ多数）。`report-u1m` で tip 連動勢が強い informed-flow（inc-zeta **64.26**）寄り。  
- **効きにくい／不確実**: venue-arb が突出する cex-drift（**73.70**）— 低閾値・単発回帰が主因の可能性が高く、本変更は閾値を下げない。crash / whale は多くのプレイヤーで最悪帯（カード・表）で、本仮説の射程外。  
- **大きさ**: zeta の −13 T 級を「回復」と主張しない。共有世界・3 seed・未検証診断（G0 BLOCKED）のため、方向仮説に留める。

## 4. 失敗条件（これが観測されたら仮説は誤り）

隔離・同条件比較で次のいずれかが起きたら仮説を棄却する。  
(1) tip=0 比率が大幅減っても、マッチ同機会の **後順位率・不利 bps・P−noop** が改善しない。  
(2) noop 増で機会を捨てた結果、最悪レジーム T または平均 T が対照（現行利益連動入札・ゼロ許容）より悪化し、かつゼロ tip 注文を残した対照の方が良い。  
(3) 提出数は同程度なのに tip 分布だけ上がり、ガス支払い増が P を食う（`ZETA2` はガス節約では説明不能と明記—逆方向の失敗）。  
(4) calm/202 型（低 tip 側が勝つ反例）が主となり、競争 tip 強制が系統的に損になる。

## 5. 必要な観測（decide() が見る現在・過去の合法な情報だけ）

レジーム名・seed・将来は使わない。  
- 各 venue の **現在の WETH/WBTC 価格・深さ・fee bps**、公正価格（既存コアと同じ合成）。  
- 自ウォレット残高（USDC / WETH / WBTC）。  
- 推定エッジ: `gapAbs − (feeBps + SAFETY)/1e4`（inc-zeta 系の raw-gap 選択）と、入札用の保守エッジ（fee 控除後。**75 bps を入札から二重控除して 0 にするのは避ける**—`ZETA2` の失敗形）。  
- メンプール／競合の **観測可能な competitor priority fee**（既存 `competitor+bump` 経路）。  
- 直近自注文の成功・リバート・送信失敗は、あれば在庫更新の入力としてのみ（レジーム推論には使わない）。

## 6. 実装の概要（どのモジュールを足す/変えるか、サイズ・入札・撤退の具体的な数値案）

**変更する因子は2つだけ: 入札 + 観測に基づく停止（noop ゲート）。** 入口閾値の数値・サイズ式・専門モジュールは触らない（ベースは inc-zeta 系: 手数料+**50 bps**、残高 **2.5〜25%**）。  

1. **選択・サイズ**: 現状どおり raw-gap ランキングと 2.5〜25%。  
2. **入札予算入力**: レガシー経路では `singleProfitEdge = gapAbs − (feeBps+50)/10000`（`ZETA2` ablation A の入力。75 bps を入札専用に重ねない）。  
3. **入札**: `bid = min( ceiling, profitShare×edge, max(default, competitor+bump) )`。数値案は inc-zeta / a30 整合: **profitShare 30%（3000 bps）**、**bump +0.1 gwei**、**default 0.1 gwei**、上限は既存 fee ceiling（観測上 0.1〜5 gwei 帯）。  
4. **ゲート（新規・安全側）**: 単脚について、`profitEdge ≤ 0` **または** キャップ後 tip が `min(ceiling, max(0.1 gwei, competitor+0.1 gwei))` に届かないなら **注文せず noop**（`ZETA2` 推奨 variant C）。バンドルは既存資金チェックを維持。  
5. **撤退**: 新規専門は足さない。過剰 WETH の無条件翌ブロックスイープは本 B0 の対象外（`ZETA2` では増幅要因だが別実験）。

## 7. 安全な出口と最悪ケース（資産損失の上限、5秒締切、無効注文の防止）

- **資産**: ゲートは「送れない注文を送らない」方向。元本の新規上限はサイズ式のまま（残高の 25% キャップ）。最悪は機会損失（noop）であり、ゼロ tip 連発による悪化 fill・リバート連鎖を減らす意図。  
- **5 秒**: 追加計算は既存エッジ・競合 tip の比較のみ。外部 I/O・探索ループを増やさない。候補は現行どおり最良ギャップ1本（または既存バンドル）に限定。  
- **無効注文**: `size > 0`、残高・dust チェック維持。tip は整数 wei・上限クリップ。`profitEdge≤0` では提出しない（zeta-2 がテストで許容した「非正でも tip=0 で送る」を禁止）。リバート理由の推測で再送ストームしない。

## 8. 既存の戦略との違い（STRATEGY-CARDS のどのプレイヤーに近いか・何が新しいか）

- **近い**: **inc-zeta**（手数料+50 bps・2.5〜25%・競合+0.1・利益の 30% まで）および利益連動入札の **opus-1 / sonnet-2**。  
- **遠い**: **venue-arb**（10 bps・固定入札・WETH 単発）、**multi-arb / clean-arb**（固定入札）、**zeta-2**（保守 75 bps を入札に載せ tip=0 を許容）。  
- **新しい点**: 「利益連動で tip を上げる」だけでなく、**競争可能 tip に届かない単脚は送らない**明示ゲート。カードの「入札ありが上位、ただし venue-arb 例外」と、回帰診断の tip=0→悪化 fill を同時に踏まえたコア修正。

## 9. 因子分類

**入札** + **観測による制限（競争不能時の noop）**。  
入口閾値・サイズ・在庫方針・専門モジュールは変更しない。利益源は公正価格ギャップ裁定のまま。
