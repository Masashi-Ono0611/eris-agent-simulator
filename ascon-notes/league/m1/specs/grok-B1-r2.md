# 仕様: 急落検知による在庫回路遮断（Defense Circuit）

## 1. 仮説（1つ）

**仮説:** 多数のプレイヤーが弱い crash / whale（および価格急変を伴う depeg）では、公正価格ギャップ裁定そのものより、**急落中に方向性を増やす買いと、直後の安値売り（在庫経路の増幅）**が相対スコアを削る。したがって、裁定核の閾値・サイズ・入札をいじらず、**観測可能な短期マーク急落と「直近買いの直後売り」を禁止する防御レイヤ**を前段に置けば、弱いレジームでの最悪寄り損失を抑えつつ、平時のギャップ裁定は維持できる。

根拠: `report-u1m.md` で多くの系統の最悪レジームが crash / whale（例: clean-arb crash 42.37、astra-2 crash 43.04、opus-1 whale 45.15、astra-1 whale 44.43）。`STRATEGY-CARDS-U1.md` は全員が同一ギャップ裁定核を共有し、構造的防御は grok-1（GMX）と opus-1（多モジュール）に偏る。`ZETA2-REGRESSION.md` は買い→次ブロックの無条件 WETH 売りが損失増幅器であること、およびゼロ優先手数料が約定品質を落とすことを実測で示す。

## 2. 利益の仕組み（なぜ他から取れるか・何を見るか）

これは**新規利益源ではなく防御**である。相対 T は「自分が稼ぐ」だけでなく「他が落とす局面で落とさない」ことで上がる。

- **資産:** WETH・WBTC（必要なら安定コインの fair も監視し depeg 用に流用）。
- **venue:** Uniswap / Balancer / Curve の各プール中値（または既存エージェントが既に使う公正価格系列）から、ブロックごとのマークを合成。
- **他参加者から取る理由（仮説）:** 急落局面でもギャップに乗って買い増し・薄い優先手数料で後追い約定し、在庫を悪化させるプレイヤーが多い（カード上ほぼ全員が同一核）。Defense Circuit は「急落中はポジション増加を止め、現金化・在庫縮小だけ許可」するため、同じフィールドで他が被るマーク損失・往復損を相対的に避ける。
- **平時:** 回路がオフなら既存のギャップ裁定・入札・専門モジュールはそのまま。

## 3. 予測（方向・大きさ・効く／効かないレジーム）

- **方向:** crash・whale・急変 depeg で最悪レジーム寄り T が改善する方向（相対）。cex-drift / informed-flow / calm ではほぼ中立〜わずかに機会損失。
- **おおよその大きさ:** 上位5体が約1T以内（CIが0を含む）なので、**全体平均 T を数ポイント押し上げる主張はしない**。狙いは「最悪レジームで他より大きく沈まない」こと。u1m の最悪レジーム差はプレイヤー間でおおむね数〜十数 T（例: crash で venue-arb 57.24 vs clean-arb 42.37）なので、防御が効けば**最悪側で数 T 規模の相対改善があり得る**、という仮説レベルに留める（未検証・性能保証なし）。
- **効くと予想:** crash、whale、価格が短時間で一方に動く depeg。
- **効きにくい／機会損失:** cex-drift（venue-arb が 73.70 で勝つような、乖離を積極的に取る局面）、informed-flow（inc-zeta 64.26）、launch / cdp の専門モジュール勝負。誤検知で回路が長くオンだと、これらで機会を落とす。

## 4. 失敗条件（これが観測されたら仮説は誤り）

次のいずれかが、同一ロスター・複数 seed の診断で安定して出たら仮説を棄却する。

1. crash / whale で、回路ありのエージェントの最悪レジーム T または P−noop が、回路なし対照より**一貫して悪化**する。
2. 回路発火中に「ポジション増加の禁止」がほとんど発動していない（急落フラグが立たない）のに、成績が変わらない／悪化する → 検知が空振り。
3. calm / cex-drift で、回路オン時間が長く、ギャップ裁定の約定数が対照より大きく減り、かつ相対 T が明確に悪化する → 誤検知コストが支配的。
4. 発火後も買い→次ブロック売りの往復損が対照と同程度残る → 「直後売り禁止」が実装・ゲート漏れ。

## 5. 必要な観測（decide() が合法に見られるものだけ）

レジーム名・seed・将来ブロックは使わない。エージェント内部メモリに、過去の自分の decide 呼び出しで得た値だけを保持する。

- **現在:** 各 venue の WETH/USDC・WBTC/USDC（および既存公正価格）、残高（USDC/WETH/WBTC）、mempool 競合手数料（既存入札ロジック用）、実行可能なプール深さ。
- **過去（自前リングバッファ）:** 直近 \(N=24\) ブロック分のマーク（例: 3 venue 中値の中央値、または既存 fair）。直近成功した自注文の `(blockSeen, base, side, qty, price)` を最大 \(M=8\) 件。
- **導出:**  
  - \(r_{short} = \mathrm{mark}_{now}/\mathrm{mark}_{now-8} - 1\)（約8ブロックの収益率）  
  - \(r_{med} = \mathrm{mark}_{now}/\mathrm{mark}_{now-24} - 1\)  
  - 「毒性フラグ」: 直近成功買いの価格が、その後の mark より \(A\) bps 以上悪化している件数。

## 6. 実装の概要（モジュール・数値案）

**ベース:** 既存のギャップ裁定核（inc-zeta / venue-arb 系の閾値・サイズ・入札）は変更しない。前段に `defenseCircuit` を追加。

**発火（Defense ON）:** 次のいずれか（WETH または WBTC のどちらか）。

- \(r_{short} \le -150\,\mathrm{bps}\)（8ブロックで −1.5%）  
- \(r_{med} \le -300\,\mathrm{bps}\)（24ブロックで −3%）  
- 安定コイン fair が 100 から \(±80\,\mathrm{bps}\) 超（depeg 用；既存に fair があれば流用）

数値の動機: カード上の通常入口が 10–60 bps 程度なので、それより大きい「トレンド急変」を通常ギャップと区別する。正確な最適値は不明なので、上記は初期案。

**Defense ON 中の行動:**

1. **ポジション増加の裁定買い禁止**（急落資産の買いレッグを noop）。売り・在庫縮小・現金化のみ許可。  
2. **サイズ:** 許可する縮小トレードは残高の最大 10%／回、かつ深さの 25% 上限（平時の 2.5–25% より抑制）。  
3. **入札:** 許可トレードは最低でも `max(0.1 gwei, competitor+0.1 gwei)`、利益連動なら利益の最大 20% まで。**ゼロ優先手数料は送らない**（`ZETA2-REGRESSION.md`: 40.81% がゼロ入札・reverts の 96% がゼロ優先、と対照の差 −13.28 T）。利益エッジが非正なら**注文自体を出さない**（ゼロ入札で送らない＝回帰の教訓）。  
4. **直後売り禁止（Anti-churn）:** 直近 2 ブロック以内に買った同一 base の数量の ≥50% を、利益無関係に売らない。例外は Defense ON かつ「マークがさらに悪化し、かつ買いコストより良い売り」のみ（縮小優先）。動機: 同報告書の買い→次ブロック Uniswap 売り現金 P（例: cdp で zeta −4045 vs incumbent −1048）。  
5. **解除:** 連続 12 ブロック、発火条件がすべて偽、かつ毒性フラグ件数 0 → OFF。チャタリング防止のヒステリシス。

**専門モジュール:** Liquity / launch / GMX は触らない（本仮説の外）。GMX 新規ヘッジは grok-1 の不正注文リスクがあるため、本仕様では採用しない。

## 7. 安全な出口と最悪ケース

- **資産損失の上限（意図）:** Defense ON 中は急落資産の新規買いを止めるので、追加の方向性エクスポージャは増やさない。既存在庫のマーク損は避けられない。Anti-churn は往復実現損の増幅を抑える。  
- **ハードキャップ案:** 1 decide あたりの想定想定元本 ≤ `min(残高の10%, 深さ25%, 5000 USDC 相当)`。エポック開始からのマーク評価が初期から −8% 超なら、縮小以外すべて noop（ドローダウン・キルスイッチ）。  
- **5秒締切:** リングバッファ更新と数個の比較のみ。プール走査は既存核に委譲。新規 RPC を増やさない。  
- **無効注文防止:** 数量≤0・残高不足・非正の保守的利益エッジ・ゼロ優先手数料をローカルで棄却。バンドルは売り在庫が揃わないなら組まない（zeta-2 の funding precheck 方針を維持）。本番に env 依存を入れない（定数をコードに埋める）。

## 8. 既存の戦略との違い

- **近い:** sonnet-1（「最悪エポックを避ける防御」、在庫帯 ±20%）の思想。ただし sonnet-1 は主に入口 60 bps・在庫帯という**核の再パラメータ**に近い。  
- **近いが採用しない:** grok-1 の GMX ヘッジ（別利益／ヘッジ源だが `sizeDeltaUsd must be positive` 系の不正注文リスクがカードに記載）。  
- **新しい点:** (1) 短期マーク急落の**明示的状態機械**、(2) 急落中の**買い禁止**、(3) **直近買いの直後売り禁止**（ZETA2 の増幅経路への直接対策）、(4) ゼロ入札禁止を防御パスに固定。ギャップ閾値 50↔60 bps のような再チューニングではない。

## 9. 因子分類

**主: 観測による制限（急落・毒性の状態機械）＋在庫（増加禁止・anti-churn・ドローダウン・キル）。**  
副次: 入札（防御中のゼロ入札禁止・下限）。  
入口閾値／サイズの平時再パラメータや、新しい専門利益モジュール（Liquity/launch/GMX）ではない。
