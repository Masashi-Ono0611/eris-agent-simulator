# M1 結果 — 16 仕様書の機構分類（2026-10-04）

仕様の生成: 提案者 4 モデル（Astra / Sonnet 5.5 / Opus 5 / Grok）× brief 2 種（B0=裁定コアの改良、B1=別の利益源または防御）× 独立 2 セッション＝16 本（原文は `specs/`）。全員に同じ資料（STRATEGY-CARDS-U1・report-u1m・ZETA2-REGRESSION）だけを渡し、互いの仕様書は見せていない。分類は作者名を隠した写し（`anon/`）を別のエージェント（Sonnet）が行い、対応表（`anon-mapping.private.json`）は分類後に開けた。性能は主張しない。3 seed の診断ではなく、まだ 1 世界も走らせていない仕様の比較である。

## 結果（measured: 分類の集計）
- **独立な機構は 6 種**。16 本のうち 14 本は他と同一機構。単独なのは F（S08）と G（S09）だけ。
- 近似コピーのペア: S06≒S15（同式・同数値）、S13≒S16、S02≒S05（−15bps・24 ブロック・履歴 8 件まで一致）、S07≒S10。
- 全 16 本が 9 節を満たし、レジーム名・seed・将来情報を入力に使う仕様は 0 本。
- **現行の公正価格ギャップ裁定の外に出る利益源を提案した仕様は 0 本**。8 本は防御、残り 8 本は ZETA2-REGRESSION が診断した zeta-2 の欠陥（ゼロ入札・無条件掃き出し）の修理案。

## モデル別の傾向（inferred: 各 4 本・1 回の生成）
- 同じ brief でも、モデル内の 2 本は同じ機構になる（Astra・Sonnet・Grok の B0 は D、Opus の B0 は E、Opus の B1 は A、Grok の B1 は B）。独立 2 セッションの再現性は高い一方、モデル間の差は大きい。
- Astra は B1 で 2 本とも別の機構（F・G）を出し、**異なる機構の数は Astra と Sonnet が 3/4、Opus と Grok が 2/4**。ただし F・G は根拠が薄い（F は根拠の実例 1 件・G は規模が小さく効果不明）。
- Opus は在庫・掃き出しと約定品質に、Sonnet は入札と在庫に、Grok は入札と在庫の価格経路に寄る。
- 「モデルが重要」の暫定証拠（計画の閾値）: 同じ brief の両反復で特定モデルだけが独立機構を出す→Astra（F・G は他のモデルが出していない）。ただし F・G の質は未検証で、運用閾値に達したとは言えない。

## 仕様の弱点（分類担当の指摘・要点）
- D: 保守利益に 75bps を引く版は実質的に入口閾値の引き上げになる（1 因子という自己申告と合わない）／競合入札の観測が全市場の最大値で、当該 venue と無関係な競争まで拾う。
- E: 強制売りを 0.1gwei のまま残すと、問題にしている漏れが戻る／漏れの根拠は「どの分岐がその注文を選んだかの証明ではない」とレポート自身が明記。
- A: 約定価格の復元方法が不明（2 レッグ束・複数 venue）／マークアウトの評価幅が仕様ごとにばらばら／較正に使った不利幅が入札順位の代理変数なら、逆選択ではなく入札を測っているだけ。
- B: 売り下げ後の買い戻し手順がない／crash の価格経路が資料にない。
- 自己矛盾・誇張の例: S02「この防御はまだ誰も持っていない」（第 8 節が近い既存を挙げている）、S07「元本全損の経路はない」と「crash の許容下落は未計測」の併存、S14 の例が inc-zeta の入口条件を通らない。引用の食い違い（不利幅の中央値 3.07〜12.81 か 3.07〜27.63 か、noop の P の下端）。
- 出典が今回の資料外で確認できないもの: S08 の型定義の行番号、S09 の GMX の注文費用、S07 の約定件数など。

## 含意（inferred）
1. 多様性は「モデルを増やす」ほど増えない。同じ証拠を渡すと、診断された欠陥の修理に収束する（D と E は ZETA2 の変種 C 等に近い）。独立な利益源を得るには、brief に反例（既存の機構を禁止する）を入れるか、証拠の見せ方を変える必要がある。
2. 因子実験（xb-core の V0〜V7）は、D 型（入札の入口条件）・E 型（掃き出し）を因子として扱えていない。次の実装候補は、A（約定品質ゲート）と D・E を 1 つずつ入れた版。
3. 仕様書のままでは測れない。M2（親から改訂させる 2×2）の前に、D・E・A のうち最も測りやすい 2 つを実装して F_ref で比べるのが筋。
